ChronoTrace Memory v0.23 已由参赛者提交 Textual Full，在线入口为 `adaptive_evidence.chronotrace_api:app`，修订为 `source-local-extents-01.contract03`；公开仓库已提供完整服务源码、运行兼容性修复及校验清单，线上部署与公开实现采用相同核心方法和接口，默认还原代码清单身份为 `4f7aa733e817f906605e6c9ef88c6a5f9e39ef54e5acaa2283e1f6ac997d8429`，最终成绩和公榜状态以赛事平台为准。运行时克隆本仓库，进入 `online/v0.23-contract03`，用 Python 3.12 执行 `python prepare_source.py --output source`，创建独立虚拟环境并安装 `source/requirements.txt`；在 Git 之外私密设置 `MEMORY_API_KEY`、`DASHSCOPE_API_KEY` 与完整的 `AE_EMBEDDING_URL`，配置 `AE_EMBEDDING_BACKEND=dashscope`、`AE_EMBEDDING_DIMENSIONS=1024`、`AE_EMBEDDING_BATCH_SIZE=10`、`AE_EMBEDDING_TIMEOUT=60`、`AE_EMBEDDING_MAX_ATTEMPTS=3`、`AE_EMBEDDING_MAX_REQUESTS=0`、`AE_MODE=query_document_evidence`、`AE_CONTEXT_CHARS=24000` 及实例独占绝对路径 `AE_DATABASE`；从 source 目录使用虚拟环境 Python 运行 `python -m uvicorn adaptive_evidence.chronotrace_api:app --host 127.0.0.1 --port 18406 --workers 1 --no-access-log`，访问基址及 HTTPS 接入由独立运行环境配置。Add 同步持久化后才返回 200，以 `(user_id, request_id)` 幂等；用户严格隔离，同用户跨会话可查；原始内容及有序 text 数组不可变，状态解释写入独立派生库；Search 按优先顺序返回不超过 `top_k` 的 `data` 证据数组，空结果为 `{"data": []}`。线上使用 `text-embedding-v4`，无生成式 LLM，最终回答和评分由平台执行，图片不支持。安装依赖后在在线目录运行 `python -m unittest discover -s . -p test_five_requirements.py -v` 验证 13 项合成接入控制，在 source 内运行 `python -m unittest discover -s tests -v` 验证 64 项服务回归；测试不代表得分提升。Full 原配置为 Add 并发 16、Search 并发 16、`top_k=100`；运行中保持代码、模型、接口及评测参数稳定，一致备份主库、envelope 和派生库，限制数据用途并在任务完成后 30 天内清理，除非另获书面许可。Windows 解释器为 `.venv\Scripts\python.exe`，Linux 为 `.venv/bin/python`；完整环境、字段和运维边界见[在线指南](../online/v0.23-contract03/RUN_GUIDE.zh-CN.md)、[API](API.md)及[部署说明](DEPLOYMENT.md)。
